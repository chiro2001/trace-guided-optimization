# 自动策略与验证口径

0.6.0起不再使用八库应用SHA配方。`--recipe auto`与`generic`根据实际ELF与画像热度选择；`eager-v12`仅为参数兼容别名，已失去特定文件身份含义。`--top`与`--image`仍约束选择范围。应用哈希只验证本次画像与输入相同，不要求输入属于发布时的列表。

普通BOLT对未来版本重新采集画像即可尝试；缺失符号、重定位、展开信息或运行时元数据时记录具体能力缺口。Go元数据由Go编译器路线处理。CPython入口/分派表按符号和指令结构识别，可选源码重建同时验证源码声明版本与SOABI、GIL、debug、trace-refs和指针宽度。

通用策略不默认启用assume-code-pages-safe。`conservative`、`balanced`与`aggressive`控制优化动作，生成失败或验证不等价时保留原版并继续其它候选。工具通过实际帮助信息发现能力，不按工具SHA选择策略。

训练/初筛只提名候选，独立确认要求每个配对均超过最小收益阈值。`evaluate --bundle`复用已选工件，改变负载命令/显式环境/目录进行留出验证，不重选候选。Python工作集最终入口还检查留出等价与最大退化阈值；不满足时发布原版。

记录配对wall、原始输出、真实加载的库/Go compiler、PMU范围及复用情况、CPU列表和失败原因。不同源码/编译参数、画像、缓存口径和优化动作分列；不能把QEMU时间视为原生收益，也不能把包装器PMU视为整个编译器树。
